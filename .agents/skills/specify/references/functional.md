# Functional kind

What matters is the *what* and the *why*, never the *how*.

There is no Solution section for `e2e` — its criteria are scenarios, and the suite is what judges them.

The generated PRD is the discovery index for functional and technical contracts. Give Scope an exact ownership boundary; regenerate the PRD after writing. Do not add categories or tags.

Amend, never fork: a requirement that changes something already implemented amends that spec rather than opening a new one. An amend is `draft` until validated again.

When a requirement touches several specs, the `/build-requested-change` orchestrator routes to coordinated delivery.
