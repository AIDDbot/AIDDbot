# s0003-review - Review of the two-loop lifecycle

## Findings

| # | Finding | Proposal |
| --- | --- | --- |
| 1 | The spec links to `intent.md#pending`. The change removed that section, as the spec asked. The build lists the broken link. The spec cannot change after approval. | Accept the broken link in a frozen spec. A spec should link to a section that its change keeps, or to the page only. |
| 2 | The `US1R3` scenario lists the shelf in an order that the old catalog did not have. The change reordered the catalog rows: project documents, then change documents in step order, and the `changelog` last. The wiki changes table of the spec did not list it. | Accepted as catalog decision 49. A scenario that says "in catalog order" should match the catalog, or the spec should list the reorder. |
| 3 | `US2R3` asks for a check against the Form values of the Tags section. The builder reads the Form tag table as a sixth contract table. `AGENTS.md`, `knowledge-wiki.md`, and `explorer-development.md` now say "six tables". | Keep it. Decide whether Life and Relevance also become contract tables. |
| 4 | Agent decisions with no person present: the phase numbers stay 0 to 3; Foundation has no `Uses`; Release uses and produces the `changelog`; intent decisions 8 to 15 replace the Pending section; catalog decision 24 is superseded by decision 50. | A person checks them when closing the change. |
| 5 | The map draws the zoom of Development as two dashed lines to the corners of the change frame. They cross the shelf band behind the document chips. | Keep it. Change it if people find it confusing. |
