# s0004 - Apply the naming review

## Problem

### Goal

Some names of the method are long or unclear, and two documents sit in the wrong step. The naming review proposals N1 to N6 in the [Pending](../../wiki/intent.md#pending) section of the intent page fix them.

### User stories

- `US1` - As a person who learns AIDDbot, I want short, clear names and the right step for each document, so that the method is easy to learn and to follow.

## Solution

| Proposal | Change |
| --- | --- |
| N1 | "Project brain" replaces "knowledge shelf" in the wiki, the glossary, and the explorer. The glossary anchor becomes `#project-brain`. The knowledge wiki is one part of the brain. |
| N2 | The document ID `agents` replaces `agent-instructions`. The explorer maps `AGENTS.md` to `agents`. |
| N3 | `roadmap` stays. Its purpose says that it holds past and future milestones. |
| N4 | `impl-plan` leaves the catalog and goes to the names for later. A `large` change tracks its progress in the Tasks of the spec. Impact levels, document IDs, status use, the Templates block, and the glossary follow. |
| N5 | Analysis writes the `feature-file`, with declarative scenarios. Design no longer produces it. The single approval at the end of Design stays. |
| N6 | Analysis uses `roadmap`, `glossary`, `wiki-page`, `domain-model`, `adr`, and `agents`. It produces `spec`, `feature-file`, and `roadmap`. |

- The proposals become decisions in the intent page and the catalog. The Pending section stays, empty, so the links of frozen specs to it still work.
- Frozen specs and review reports keep the old names.

### Tasks

- [x] Change the wiki pages, `AGENTS.md`, and `CHANGELOG.md`. Check: `US1R1`, `US1R2`, and no broken link in the build.
- [x] Change the explorer labels, data names, and tests. Check: `US1R3`, `bunx tsc --noEmit`, `bun test`.
