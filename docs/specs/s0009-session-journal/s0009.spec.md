# s0009 - Keep a session journal

## Problem

### Goal

[Routine maintenance](../../process/documentation-catalog.md#routine-maintenance) needs no spec, and the commit explains the diff. But the context of a session is lost: what changed in a day, and why. The `notepad` keeps only the last session. This change applies the agreed proposals J1 to J10 of the [documentation catalog](../../process/documentation-catalog.md#session-journal). It starts after [`s0008`](../s0008-folders-by-kind/s0008.spec.md), because the journal uses the `docs/product/` folder.

### User stories

- `US1` - As a person or an agent who works on AIDDbot, I want a short journal of each day with work, with a link to each commit, so that small changes without a spec keep their context.

## Solution

1. **Documentation catalog.**
   - Add the type `journal`: Life `LIVE`, Form `DOC`, Relevance `COULD`, Standards `META`, Kind `PRODUCT` (J3, J7, J8).
   - Add a Session journal section next to Session handoff with the rules J1, J2, J4, J5, and J6: one file for each day in `docs/product/journal/<yyyy-mm>/<yyyy-mm-dd>.md`, one line for each change with a link to its commit, no files or diffs, read only on demand, written after the other commits as `chore(journal)`.
   - Add a decision for the change, and remove the Pending section "Session journal".
2. **Glossary.** Add the term Journal.
3. **Scaffolding.** Add `docs/product/journal/` to the layout and to "When each folder appears". The journal rule ships with the process (J10).
4. **Agent instructions.** `AGENTS.md` asks for the journal entry at the end of a session, next to the `notepad`.
5. **Explorer.** Read `docs/product/journal/**/*.md` as documents of type `journal` (J9). Update the content scope in `explorer-development.md`. The brain contract keeps its headings and columns.
6. **First entry.** Write `docs/product/journal/2026-11/2026-11-26.md` for the session that agreed on the journal.

## Verification
