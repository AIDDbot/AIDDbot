# s0007 - Separate the project brain from the knowledge wiki

## Problem

### Goal

`docs/wiki/` holds the original AIDDbot documents, but the glossary says that the wiki is only one part of the project brain. The two definitions contradict each other, and the model is hard to explain. This change applies the agreed brainstorm decisions W1 to W8 of the [knowledge wiki](../../wiki/knowledge-wiki.md#pending):

- The project brain is all the documentation that people, agents, and skills create.
- The knowledge wiki is a small map of the brain and the code. Only agents write it. It owns no facts.
- Each document is process, product, or technology.

The code map page, the wiki skills, the explorer for teams, and the installer are not part of this change.

### User stories

- `US1` - As a person or an agent who works on AIDDbot, I want the original documents grouped by kind and the wiki as a map of them, so that I know where the truth is and where each new document goes.

## Solution

1. **Move the original documents** out of `docs/wiki/` with `git mv`, into one folder for each kind (W7):

   | Folder | Kind | Documents |
   | --- | --- | --- |
   | `docs/process/` | Process | `documentation-catalog.md`, `knowledge-wiki.md`, `aiddbot-cli.md` |
   | `docs/product/` | Product | `intent.md`, `glossary.md` |
   | `docs/technology/` | Technology | `scaffolding.md`, `cli-development.md`, `explorer-development.md` |

   The root documents (`ROADMAP.md`, `DESIGN.md`, `AGENTS.md`, `README.md`, `CHANGELOG.md`) and `docs/PLAN.md` stay where they are.
2. **The wiki keeps only `index.md`.** It becomes the agent map of the brain: it links to every brain document, grouped by kind. Agents write it (W2, W3, W6).
3. **Documentation catalog.**
   - Add the tag **Kind**, with the values `PROCESS`, `PRODUCT`, and `TECH`, to every document type.
   - Add the type `page`: a prose `LIVE` document about one topic, written by people. The moved documents use it.
   - `wiki-page` becomes a page that agents write from the brain and the code.
   - The project brain is all the documentation (W1), not only the `LIVE` `DOC` types. Update decision 19 and add a decision for the change.
4. **Knowledge wiki.** Rewrite its Model with W1 to W8 and remove the Pending section.
5. **Glossary.** Fix "Project brain" and "Knowledge wiki". Add the terms Process, Product, and Technology for the three kinds.
6. **Scaffolding.**
   - Layout: add `docs/process/`, `docs/product/`, and `docs/technology/`. `docs/wiki/` holds the agent map.
   - "When each folder appears": add the three folders in `M0`, from this spec. Change the `docs/wiki/` row: the wiki is the agent map of the brain.
   - "What ships": AIDDbot ships only process (W7), inside its skills, templates, and CLI. The product and technology documents stay in this repository.
7. **Explorer.** Update the fixed paths in `chapters.ts` and `documents.ts`, the folders that it reads, and the wiki contract in `explorer-development.md`. The seven tables keep their headings and columns. The brain map follows the new brain definition only if the catalog tables need no new column for it.
8. **Links and other documents.** Update every relative link, `AGENTS.md`, `README.md`, and `CHANGELOG.md`.

## Verification

- [ ] `US1R1` - The repository shall keep the moved documents in `docs/process/`, `docs/product/`, and `docs/technology/` as the Solution table says, and `docs/wiki/` shall hold only `index.md`, with a link to every brain document.
- [ ] `US1R2` - The glossary, the documentation catalog, the knowledge wiki, and the scaffolding pages shall state W1 to W8 with no contradiction, and the knowledge wiki shall have no Pending section.
- [ ] `US1R3` - When a person runs the link check, `bun test`, `bunx tsc --noEmit`, and the explorer build, each one shall pass with no broken relative link or anchor.
