# AIDDbot

This is not a traditional application. There is no application source code to build or test. 

The deliverable are **agent skills** tailored to implement AI-Driven Development (AIDD) workflows.

## Skills

- Folder: `.agents/skills/`
- Inventory, pipeline, and SDLC coverage: [`.agents/skills/skills.catalog.md`](./.agents/skills/skills.catalog.md) — it owns the routing, so skills never narrate it
- Human-oriented workflow docs are in [`docs/`](./docs/)

## Editing skills

- A skill is short prose an agent reads, never pseudocode: `SKILL.md` in English, same voice as a command. Follow [`.agents/skills/skillify/assets/skill.template.md`](./.agents/skills/skillify/assets/skill.template.md). Always create or fix skills via [`/skillify`](./.agents/skills/skillify/SKILL.md) — do not edit skills ad hoc.
- Write only what a capable agent would get wrong on its own. Drop role (the agent file already has it) and workflow (the command already has it). Never paraphrase a linked template — the template in `assets/` is the artifact's spec.
- Put guides and long checklists in `references/`; put templates in `assets/`. Link them from the skill (same skill folder only).
- Put paths, slugs, personality, git rules, and the spec status chain in the consumer `{Agents_File}` (generated by `/explore` from `explore/assets/AGENTS.template.md`); put skill-specific rules in that skill's `SKILL.md`.
- Commands live in `.agents/commands/` as `{name}.command.md`.
- After changing a skill or command, align the docs `/skillify` tracks:
  - its `SKILL.md` (or `.command.md`)
  - the [catalog](./.agents/skills/skills.catalog.md), when behavior, paths, or routing changed
  - the root [README](./README.md) and [workflow](./docs/AIDD.workflow.md), only when what a human is told changes
